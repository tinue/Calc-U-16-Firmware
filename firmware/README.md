# calcu16-fw: the firmware

Calc-U-16 firmware for the SwissMicros DM16L, written in Rust and running natively on the calculator. It is at an early stage:
- the hardware is fully driven by our own code: the LCD, the keyboard, the serial port, sleep and wake-up, the bootloader entry;
- the calculator itself is a small integer calculator, with algebraic entry in strict order of entry.

## What it does

| Keys | Function |
|---|---|
| `0`–`9`, `A`–`F` | digit entry (digits invalid in the current base are ignored) |
| `+` `−` `×` `÷` | 2's complement arithmetic, strictly in order of entry: `5 + 4 × 3 ENTER` gives 27, and `×` already shows the intermediate 9. Two operators in a row: the second wins. ÷ is signed, ÷0 shows `Error 0` |
| `ENTER` | `=`: completes the pending operation; the result can be used as the next left operand |
| `f` `STO` | WSIZE: X is the new word size (`16 f STO`), `0` means 64, above 64 shows `Error 2`. The number shown before the size was typed comes back, truncated to the new size. Default: 32 |
| `HEX` `DEC` `OCT` `BIN` | display base |
| `←` | delete the last digit, or clear X |
| `CHS` | negate |
| `f` `+` / `f` `−` | LCD contrast up / down (shows `EV nn`) |
| `R/S` held | status display: word size and sign mode (`32 2C`) |
| `ON` | off / on (deep sleep; the stack is kept) |
| `D` held while pressing `ON`, or held at reset | enter the ISP bootloader |

**Display** (the layout from `docs/requirements.md`):
- Bottom line: X in the selected base, with its suffix (`h`, `d`, `o`). Top line: X in DEC, or in HEX when the base is DEC.
- BIN has its own screen: up to 16 bits in one line, up to 32 in two lines of 16, up to 64 in two lines of 32.
- A pending `f` shows at the top left. Decimal shows signed values.

**Serial port** (38400 8N1, via USB): prints `Calc-U-16` at start-up and `key row-col` for every key press. A small monitor for hardware bring-up accepts these commands (the firmware polls every 10 ms, so send longer lines in chunks of about 8 bytes):

| Command | Effect |
|---|---|
| `bootloader` | enter the ISP bootloader (used by `tools/flash.py`) |
| `peek A` / `poke A V` | read / write a 32-bit register (hex) |
| `scan` | raw key matrix: ON flag, then one hex digit of row bits per column |
| `probe` | drive each column low and print all port levels |
| `hunt` | drive every spare GPIO low in turn and report which pins follow it (finds matrix wiring with a key held) |
| `lcd` | re-initialise the LCD |

Tested on the real DM16L: keys, all four bases, `Error 0`, off/on with the stack kept, contrast (EV 0 is best), start-up after the reset button.

**Out of scope:** complement modes, carry/overflow, flags, f/g functions other than WSIZE and contrast, programming, floating point, auto-off and the RTC.

## Layout

| Path | Contents |
|---|---|
| `calc/` | hardware-independent RPN core, display model and renderer (`display.rs`), pixel fonts (`fonts.rs`, generated by `tools/display_lab/gen_fonts.py`); `no_std`, unit-tested on the host |
| `dm16l/` | board support and main loop for the LPC111x: `regs.rs` (register access), `lcd.rs`, `keys.rs`, `uart.rs`, `power.rs` |
| `tools/lpc_image.py` | patches the LPC vector checksum, refuses Code Read Protection (CRP) patterns, writes Intel HEX |
| `build.sh` | builds `target/calcu16-fw.hex` |

## Toolchain (one-time)

```sh
brew install rustup                       # keg-only, alongside Homebrew's rust
export PATH=/opt/homebrew/opt/rustup/bin:$PATH
rustup toolchain install stable --target thumbv6m-none-eabi
rustup component add clippy rustfmt
```

`build.sh` puts rustup's cargo first on `PATH` itself. `arm-none-eabi-objcopy`/`size` come from the Arm GNU toolchain (`brew install --cask gcc-arm-embedded`).

## Build and test

```sh
./build.sh                                  # → target/calcu16-fw.hex
PATH=/opt/homebrew/opt/rustup/bin:$PATH cargo test   # calc unit tests (host)
cd ../sim && cargo test --release           # simulator scenarios incl. tests/scripts/fw_*.vs
cargo run --release -- run ../firmware/target/calcu16-fw.hex   # interactive
```

## Flashing the real calculator

> **⚠ At your own risk.** Flashing can brick your DM16L. The author accepts no responsibility, will not help with recovery and will not pay for anything; SwissMicros will most likely not help either. Flashing has only been tested from a Mac running macOS; anything else is completely untested. Read the [warning in the main README](../README.md#-warning-flashing-is-entirely-at-your-own-risk) first.

The quick way is the guided script. It finds the USB port, tries to start the bootloader over the serial port, and otherwise tells you which keys to press. It then checks that the bootloader answers, flashes with verification, and shows the calculator's start-up message:

```sh
tools/flash.py                     # flash firmware/target/calcu16-fw.hex
tools/flash.py --vendor DM16_MC0   # restore the SwissMicros firmware
```

The manual steps, for reference:

**Flashing erases the calculator's memory.** Save it first: start the vendor serial console (calculator off, hold C, press ON), then send `s`, as with the earlier dump in `tools/analysis/`.

1. **Start the ROM bootloader.**
   - From the vendor firmware: calculator off, hold D, press ON. Or type `bootloader` three times on its console.
   - From calcu16-fw: hold D and press ON, or send `bootloader`.
   - The vendor firmware shows "READY FOR FLASHING".
2. **Flash** (`lpc21isp` is installed):
   ```sh
   lpc21isp firmware/target/calcu16-fw.hex /dev/cu.usbserial-0001 115200 12000
   ```
   `lpc21isp` resets the chip into the new firmware at the end. If the screen stays blank, press the reset button.
3. **Restore the vendor firmware** the same way. The unit originally ran `DM16_MC0_V34`:
   ```sh
   lpc21isp vendor/DM16_MC0_34.hex /dev/cu.usbserial-0001 115200 12000
   ```
   Then restore the memory with the console's `l` command.

### If something goes wrong on the hardware

| Symptom | What to do |
|---|---|
| Blank display, but `Calc-U-16` appears on the serial port | The LCD contrast may be off. Try `f +` or `f −` several times. The firmware uses the vendor's cold-start values (regulator 5, EV 0). |
| The calculator does not wake up after `ON` | Press the reset button (back of the PCB, lower left). |
| Nothing works | Hold D while pressing the reset button. The firmware checks D before it touches anything else and jumps to the bootloader. |
| Not even that | Without D, there is no way into the bootloader on our unit: the **PGM** button next to RESET has no effect there (see `docs/hardware.md`). What remains is hardware recovery: PIO0_1 held low during reset (a wire to the pin), or an SWD debug probe. This is why the D escapes are tested in the simulator and must never break. |
